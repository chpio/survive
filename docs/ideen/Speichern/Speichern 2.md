- **Grundprinzip**: Gespeichert werden nur Abweichungen vom Tiled-Stand, verteilt auf unveränderliche Chunk-Dateien mit Content-Hash als Namen. Ein Index pro Spielstand verweist auf die Chunks.
- **Schlüssel**: Nicht den Dateinamen der Karte verwenden, sondern IDs, die Umbenennen und Verschieben überstehen.
- **Objekt-ID**: Jedes Objekt bekommt eine eigene, dauerhafte ID als Custom Property. Die Tiled-ID taugt nicht, weil Tiled sie beim Einfügen in eine andere Karte neu vergibt.
- **Gruppen-ID**: Zweite ID pro Objekt, zeigt auf die Karte, in der es angelegt wurde. Sie ändert sich nie, auch beim Verschieben auf eine andere Karte nicht.
- **Chunking**: Die Gruppen-ID ist der Chunk. So ist der Zustand immer direkt auffindbar, zusammengehörige Objekte liegen meist im selben Chunk, und beim Speichern wird wenig neu geschrieben.
- **Verworfen**: Raster für Objekte (Zustand geht beim Verschieben verloren) und Hash-Bucketing über die UUID (keine räumliche Gruppierung).
- **Tiled-Skript**: JavaScript im Extensions-Ordner, hängt sich an `tiled.assetAboutToBeSaved`. Setzt fehlende Objekt-IDs und Gruppen automatisch, damit nichts vergessen wird.
- **Doppelte IDs in einer Karte**: Entstehen beim Duplizieren. Das Objekt mit der niedrigsten Tiled-ID behält die ID, die anderen bekommen eine neue, weil Tiled-IDs pro Karte hochzählen.
- **Doppelte IDs über Karten**: Das Skript sieht nur die aktuelle Karte und kann Verschieben nicht von Kopieren unterscheiden. Ein CI-Test findet solche Fälle, entschieden wird von Hand.
- **CI-Test**: Prüft alle Karten auf fehlende und doppelte IDs.
