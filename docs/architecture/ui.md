# HUD

The concept is in `docs/ui-events.md`.

The HUD (`src/ui/`) is a Dioxus Native document (Blitz, painted with Vello) rendered into a fullscreen image. Its styles are in `assets/ui/style.css`, loaded as a `Stylesheet` asset and hot-reloaded like the other assets; the HUD stays empty until it is loaded. The document has no user-agent stylesheet, so every element starts with CSS's initial values (`display: inline`, unsized checkboxes, visible `<style>` text); the base section at the top of `style.css` sets what the HUD's elements need, and new kinds of elements may need an entry there. `sync_state` writes the game state into one `hud::State` signal and handles the `hud::Action`s the HUD sends back over a channel. The HUD is only painted and rendered again after a mouse button or touch, a state change, a resize or a redraw request from Blitz (which also covers mouse moves that change the hover state); anything else that should change its look (e.g. animations) has to set `needs_paint`. On a window resize, `ui::resize` invalidates every node's layout cache and marks its overflow for recomputation; Blitz does neither on its own, which left centered text misplaced and, after the window grew, the HUD outside the area hit tests reach. Blitz gets all mouse input and touches (as pointers with a finger id; winit 0.30 has no pen API: under X11 pens arrive as mouse input, under Wayland not at all, see `TODO.md`); where the topmost element or an ancestor has the class `blocks-pointer` (`ui::blocks_pointer`), the picking backend `pick_hud` reports a hit on the HUD's image (`ui::Hud`) above the sprites, so picking in the game world only happens elsewhere (`docs/ui-events.md`). Bevy's own `ui_picking` is off, since it would hit the fullscreen image everywhere. The HUD and the game world scale with the window by the same rule, so they cover the same part of the screen at 1080p and 4K, only sharper, and a window wider or taller than 16:9 shows more of the world in that direction: `ui::hud_scale` gives one physical pixel per CSS pixel at `ui::REFERENCE_SIZE` (1920×1080, in the window's tighter direction), times `ui::BASE_SCALE` (1.25, the size at 100 %) and `Settings::ui_scale`, independent of the system's scale factor, and the camera (`ScalingMode::AutoMin`) shows at least `world::VIEW_SIZE` (500×281 px, the same aspect ratio) at zoom 1; `forward_input` and `pick_hud` convert Bevy's logical pointer positions accordingly.
